# Mergo: каталог техники, этап 1 — дизайн

- Дата: 2026-11-20
- Статус: одобрено 2026-11-20
- Репозиторий: `IKY4223/nextjs-shop`

## 1. Зачем

Mergo — агрегатор объявлений о технике в Узбекистане. Новые товары из магазинов и б/у от частных продавцов показываются в одном месте, у каждого предложения есть ссылка на первоисточник. Корзины и оформления заказа нет: покупка происходит у продавца.

Почему это нужно: рынок раздроблен (OLX.uz, Uzum Market, Telegram-каналы, отдельные магазины), а поиск на OLX и Uzum плохой. Человек открывает 3–5 сайтов, чтобы сравнить «новый» и «б/у». Главное преимущество Mergo — **почти безупречный поиск и подробные фильтры**.

Сначала это проект для портфолио. Если появится реальная возможность — стартап. Поэтому этап 1 должен выглядеть законченным продуктом и закладывать структуру под реальные данные, но работает на моковых данных.

## 2. Цели этапа 1

1. Каталог 4 категорий: процессоры, видеокарты, материнские платы, оперативная память. В каждой 8–12 реальных моделей (названия реальные, предложения выдуманные).
2. Фильтры: характеристики категории (3–5 на категорию), бренд, цена, состояние (новый / б/у). Состояние фильтров хранится в URL — ссылкой на подборку можно поделиться.
3. Страница товара: таблица характеристик и список предложений (тип источника, продавец, состояние, цена, город, дата обновления, кнопка «Перейти к продавцу»).
4. Поиск по `Ctrl+K` (и `⌘K`): уровни 0–1 и разбор простых фраз правилами (раздел 7).
5. Плавные переходы через React `<ViewTransition>`: картинка карточки перетекает в картинку на странице товара; сетка плавно перестраивается при смене фильтров.
6. Интерфейс на узбекском (латиница, по умолчанию) и русском.
7. Тёмная и светлая тема (палитра Electric Blue), по умолчанию — системная, переключатель в шапке, без мигания при загрузке.
8. Плашка «Демо», страница «Источники фото», малозаметная ссылка на неё в футере.

## 3. Не-цели этапа 1

- Реальные данные и их импорт (Telegram-бот, фиды магазинов, импорт по ссылке), база Neon, миграции.
- Авторизация, избранное, уведомления о снижении цены.
- Разбор запросов через LLM, автоперевод, векторный поиск.
- Корзина и заказы — не будет вовсе.
- Категории кроме четырёх; кириллическая версия узбекского интерфейса; цены в долларах.
- Деплой.

## 4. Анти-цели (провал, даже если всё работает)

- **Чужие данные без права.** Никакого парсинга, даже для моков. Продавцы в моках выдуманные. Реальные названия площадок (OLX, Uzum, конкретные магазины) в моковых предложениях не используются — только типы источников («Магазин», «Telegram», «Объявление») и выдуманные имена продавцов. Ссылки «Перейти к продавцу» в моках ведут на заглушку внутри сайта, а не на чужие страницы. Это правило действует **до релиза**, пока данные выдуманные. После релиза реальные названия площадок и ссылки на настоящие объявления появляются только вместе с реальными данными, полученными легально (Telegram-бот с согласия продавца, фиды магазинов по договорённости).
- **Сайт можно принять за настоящий магазин** с реальными ценами.
- **Поиск не лучше, чем у OLX:** опечатка, латиница вместо кириллицы или сленг не находят товар.
- **Структура, которую придётся выбросить** при подключении базы: страницы читают данные только через слой доступа (раздел 6.1).

## 5. Ограничения

- Next.js 16.4.6 (App Router; `proxy.ts` вместо `middleware.ts`), React 19.3.1, Tailwind CSS v4, TypeScript 6.0.3, Prisma 7.10.1. В проекте есть `AGENTS.md`: перед кодом читать документацию в `node_modules/next/dist/docs/` — API этой версии отличаются от прежних.
- `main` защищён: работа в ветке, merge через PR. CI: `format:check`, `prisma format` без изменений, `prisma validate`, `prisma generate`, `lint`, `build`, плюс CodeQL.
- Новые зависимости: только `fuse.js` (нечёткий поиск) и `vitest` (dev, тесты логики). Остальное — встроенные средства (`Intl`, CSS-переменные, `<ViewTransition>`).
- **Фото товаров:** только свободные лицензии (CC0, CC BY, CC BY-SA с Wikimedia Commons или Flickr), только фото именно этой модели. Нет подходящего — картинка-заглушка категории (SVG). Файлы хранятся в `public/products/`. Подписей под фото нет; автор, лицензия и ссылка — только на странице «Источники фото».
- **Деньги:** целые суммы в сумах (UZS), без тийинов. В приложении тип `number` (безопасно до ~9·10¹⁵), в схеме Prisma — `BigInt`; преобразование в одном месте слоя доступа (сейчас не нужно — данные в TS).
- Доступность: контраст палитры проверен (все пары ≥ 4.5:1); диалог поиска управляется с клавиатуры (фокус внутри, `Esc` закрывает); при `prefers-reduced-motion` анимации переходов отключаются.
- **Магазин будет расти:** позже появятся смартфоны, ноутбуки и другая техника, мебель, машины. Поэтому всё знание о категории (фасеты, подписи, синонимы для поиска, какие характеристики показывать чипами на карточке) живёт **только** в конфиге категорий. Ни один компонент не ветвится по slug категории. Дерево категорий должно принимать «Техника → Смартфоны», «Мебель», «Авто» без изменений кода. Цена в схеме — `BigInt`, потому что машины дороже 2,1 млрд сум не помещаются в `Int`.

## 6. Подходы и решения

### 6.1 Доступ к данным

- **Выбрано:** слой `src/lib/catalog/` с функциями вроде `listProducts(categorySlug, filters)`, `getProduct(slug)`, `getSearchIndex(lang)`. Сейчас они читают TS-модули с моками, позже — Prisma. Страницы и компоненты никогда не импортируют моки напрямую. Фильтрация выполняется на сервере по `searchParams`.
- Отклонено: JSON в `public/` с загрузкой в браузере — теряется серверный рендеринг и SEO.
- Отклонено: Prisma с локальной SQLite сейчас — потом смена провайдера и лишние миграции; Neon отложен.

### 6.2 Характеристики

- Категории и их фильтры описаны в TS-конфиге. Моки проверяются по конфигу через `satisfies`: опечатка в ключе или значении фильтра ломает сборку.
- В схеме Prisma у товара поле `specs Json`. Категории переедут в таблицу, когда появится админка.
- Отклонено: EAV-таблицы и отдельная таблица характеристик на каждую категорию — слишком тяжело для этапа с моками.

### 6.3 Языки

- Встроенные средства Next.js по официальному гайду `node_modules/next/dist/docs/01-app/02-guides/internationalization.md`: все страницы под `app/[lang]/`, `proxy.ts` перенаправляет на язык (cookie → `Accept-Language` → `uz`), словари `dictionaries/uz.json` и `dictionaries/ru.json`. TypeScript проверяет, что ключи словарей совпадают.
- Адреса одинаковые для обоих языков, меняется только префикс: `/uz/c/cpu`, `/ru/c/cpu`. `hreflang` для обеих версий.
- Подписи категорий и фильтров — в конфиге категорий как `{ uz, ru }`. Названия моделей не переводятся.
- Формат цены: `uz` — `Intl.NumberFormat('uz-Latn', { style: 'currency', currency: 'UZS', maximumFractionDigits: 0 })` даёт `4 500 000 soʻm`. Для `ru` `Intl` выводит `UZS`, поэтому число форматируется отдельно и добавляется «сум». Склонения — `Intl.PluralRules`.
- Отклонено: `next-intl` — лишняя зависимость для двух языков.

### 6.4 Тема

- Цвета — CSS-переменные на `:root` для двух тем, атрибут `data-theme` на `<html>`. В Tailwind v4 — `@custom-variant dark` по этому атрибуту.
- Выбор хранится в cookie. **Сервер эту cookie не читает:** вызов `cookies()` в корневом layout сделал бы все страницы динамическими, включая страницы товаров, которые могут быть статическими. Тему ставит маленький встроенный скрипт в `<head>` до отрисовки: читает cookie, без неё берёт `prefers-color-scheme`, и выставляет `data-theme` на `<html>`, поэтому мигания нет.
- Палитра Electric Blue:

| Токен            | Тёмная    | Светлая   |
| ---------------- | --------- | --------- |
| bg               | `#0A0E1A` | `#F8FAFF` |
| surface          | `#111729` | `#FFFFFF` |
| border           | `#1F2740` | `#DFE5F5` |
| text             | `#E6ECFA` | `#0E1530` |
| muted            | `#98A2BD` | `#4A5578` |
| accent           | `#60A5FA` | `#1D4ED8` |
| on-accent        | `#0A0E1A` | `#FFFFFF` |
| used (метка б/у) | `#F472B6` | `#BE185D` |
| chip             | `#1A2236` | `#EEF2FC` |

- Шрифты: текущие Geist и Geist Mono из шаблона (характеристики — моноширинным). Подмножества `latin`, `latin-ext` и `cyrillic` (проверено по `font-data.json` из `next`: у обоих шрифтов кириллица есть; узбекские `oʻ`, `gʻ` — символ U+02BB из латинского диапазона Google Fonts).

### 6.5 Поиск

- Индекс поиска (около 40 товаров) строится на сервере и отдаётся в диалог `Ctrl+K`; поиск выполняется в браузере через Fuse.js. На этапе с базой поиск переедет в PostgreSQL (`pg_trgm`), функция нормализации останется общей.
- Подробности — в разделе 7.

## 7. Поиск, этап 1

Каждый запрос и каждое поле индекса проходят одну и ту же нормализацию:

1. **Нормализация:** `NFKC`, нижний регистр; варианты апострофа `ʻ ' ‘ ’ \`` приводятся к одному; кириллица (русская и узбекская) транслитерируется в латиницу для сравнения, поэтому «процессор», «protsessor» и «процесор» совпадают. Номера моделей приводятся к одному виду: «i5 12400f», «i5-12400F», «12400ф» → одна форма.
2. **Словарь синонимов и сленга** (ru и uz) по категориям: «видюха», «видеокарта», «videokarta» → GPU; «проц», «protsessor» → CPU; «оперативка», «ozu», «ram» → RAM; «мать», «материнка», «ona plata» → материнская плата. Бренды и серии тоже: «радеон» → Radeon, «джифорс» → GeForce.
3. **Опечатки:** нечёткое сравнение Fuse.js.
4. **Разбор фраз правилами:** цена («до 3 млн», «3 mln gacha», «от 1 до 2 млн», «500 тыс»), состояние («б/у», «бу», «ishlatilgan», «новый», «yangi»), категория по синонимам. Разобранное показывается чипами над результатами («Видеокарты», «Б/у», «до 3 000 000»), каждый чип можно снять. По `Enter` — переход в каталог категории с этими фильтрами в URL.

Проверка качества: файл с не менее чем 30 запросами и ожидаемыми товарами или фильтрами (смесь языков, письменностей, опечаток, сленга) прогоняется в Vitest и в CI.

## 8. Модель данных этапа 1

TS-типы повторяют будущую схему Prisma.

- **Category:** `slug`, `name: { uz, ru }`, `parentSlug?` (дерево: «Техника» → «Комплектующие» → «Процессоры»), `facets: Facet[]`.
- **Facet:** `key`, `label: { uz, ru }`, `type: 'enum' | 'number' | 'boolean'`, для `enum` — список значений с подписями, `unit?`. Числовые фильтры — диапазон или набор значений (на выбор разработчика по удобству).
- **Product:** `id`, `slug`, `categorySlug`, `brand`, `name` (модель, не переводится), `specs` (ключи и значения из фасетов категории), `image?: { src, author, license, sourceUrl }`.
- **Offer:** `id`, `productId`, `source: { type: 'store' | 'telegram' | 'classified', name }`, `condition: 'new' | 'used'`, `priceUzs`, `city`, `url`, `updatedAt`.

Фасеты категорий:

| Категория                         | Фасеты                                                                                                                                                                       |
| --------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Процессоры (`cpu`)                | сокет (AM5, AM4, LGA1851, LGA1700), поколение/серия (Ryzen 9000, Ryzen 7000, Ryzen 5000, Core Ultra 200S, Core 14-го и 12-го поколения), количество ядер, встроенная графика |
| Видеокарты (`gpu`)                | производитель GPU (NVIDIA, AMD, Intel), серия (GeForce RTX 50 / 40, Radeon RX 9000 / 7000, Arc), объём видеопамяти                                                           |
| Материнские платы (`motherboard`) | сокет, чипсет (например B650, X870, B860, Z890, B760), форм-фактор (ATX, Micro-ATX, Mini-ITX), тип памяти (DDR4, DDR5)                                                       |
| Оперативная память (`ram`)        | тип (DDR4, DDR5), объём комплекта, частота (MT/s), количество модулей                                                                                                        |

Общие фильтры для всех: бренд, цена, состояние.

**Изменения схемы Prisma** (без миграции, только `validate` и `generate`): у `Product` добавить `categorySlug`, `brand`, `specs Json`, поля фото; добавить модель `Offer` (цена `BigInt`); удалить `Order`, `OrderItem`, `OrderStatus` и связь `User.orders` — заказов в агрегаторе нет. `User` и `Role` остаются для будущей авторизации.

## 9. Страницы

| Адрес                  | Что на ней                                                                                   |
| ---------------------- | -------------------------------------------------------------------------------------------- |
| `/[lang]`              | главная: поиск и плитки категорий                                                            |
| `/[lang]/c/[category]` | каталог: фильтры в левой панели (на телефоне — выдвижная панель), сетка карточек, сортировка |
| `/[lang]/p/[slug]`     | товар: фото, характеристики, предложения (сортировка по цене), переход к продавцу            |
| `/[lang]/search?q=`    | поиск по всем категориям: чипы разобранных фильтров и сетка карточек                         |
| `/[lang]/credits`      | источники фото                                                                               |

На всех страницах: шапка (логотип Mergo, кнопка поиска с подсказкой `Ctrl K`, переключатели языка и темы), плашка «Демо», футер со ссылкой на источники фото.

Карточка в каталоге: фото, модель, 2–3 главных характеристики чипами, строка «Новый · N · от X сум» и строка «Б/у · N · от Y сум» (если такие предложения есть), кнопка «Сравнить предложения».

Адреса категорий плоские (`/c/cpu`) при любой глубине дерева; хлебные крошки строятся по дереву.

## 12. Решения, принятые без отдельного обсуждения (проверь)

1. До релиза в моках нет реальных названий площадок, ссылки продавцов ведут на заглушку (раздел 4). После релиза — реальные источники вместе с легально полученными данными.
2. Убираем `Order` и `OrderItem` из схемы.
3. Цены только в сумах; в приложении `number`, в базе `BigInt`.
4. Добавляем `vitest` и шаг тестов в CI.
5. Шрифты Geist оставляем, добавляем кириллицу.
6. Поиск этапа 1 работает в браузере по индексу, а не на сервере.
7. Адреса: `/c/...` для категорий, `/p/...` для товаров, `/search?q=...` для поиска по всем категориям.
8. **Цена и состояние фильтруют предложения, а не товары.** Товар попадает в выдачу, если у него есть хотя бы одно предложение, подходящее под фильтры цены и состояния. Карточка показывает сводку только по подходящим предложениям. Пример: «б/у, до 3 млн» показывает процессор, у которого есть б/у предложение за 2,8 млн, даже если новые стоят 4 млн, а на карточке видна только строка «Б/у · от 2 800 000».
9. **Бренд — производитель самого товара.** Для видеокарты это партнёр (ASUS, MSI, Gigabyte), для процессора — AMD или Intel. Производитель чипа видеокарты (NVIDIA, AMD, Intel) — отдельный фасет. Видеокарты в моках — партнёрские модели, например «ASUS Dual GeForce RTX 5070».
10. **`Enter` в поиске:** если запрос однозначно указывает на одну категорию — переход на страницу этой категории с разобранными фильтрами и текстом в URL; иначе — страница `/[lang]/search?q=...` с товарами из всех категорий и теми же чипами.
11. **Родительские категории** («Техника», «Комплектующие») имеют свою страницу `/c/[slug]` с плитками дочерних категорий, без сетки товаров.
12. «Перейти к продавцу» в моках ведёт на внутреннюю страницу-заглушку с текстом «Это демо: здесь будет переход к объявлению у продавца».
13. **Весь проект на TypeScript** (сайт, позже бот и импорт фидов), общие типы и нормализация поиска. В `tsconfig.json`: `allowJs: false` и `noUncheckedIndexedAccess: true` (согласовано 2026-11-20).
