# Mergo: этап 2, Telegram-бот для продавцов — дизайн

- Дата: 2026-11-22
- Статус: одобрено 2026-11-22
- Репозиторий: `IKY4223/nextjs-shop`
- Предыдущий этап: `2026-11-20-mergo-catalog-design.md` (каталог, Neon, Vercel — готовы)

## 1. Зачем

Сейчас на сайте только выдуманные предложения. Нужны настоящие: частные продавцы публикуют объявления о б/у технике через Telegram-бота, с согласия продавца, без парсинга чужих площадок. Бот выкладывает объявление как ещё одно предложение на странице товара из каталога, рядом с магазинами, чтобы цены можно было сравнивать.

Первыми продавцами будут случайные люди, и владелец не сможет проверять сотни объявлений вручную. Поэтому проверка автоматическая, а владельцу приходит только спорное.

## 2. Цели

- Продавец публикует объявление за 1–2 минуты из Telegram, на узбекском или русском.
- Объявление привязано к товару каталога и появляется на сайте в течение минуты.
- Три исхода проверки: разрешено (публикуется сразу), запрещено (отклоняется с причиной), спорно (решает владелец).
- Работает без платного LLM. LLM добавляется позже без переделки бота.
- Расходы на первом этапе около нуля.

## 3. Не цели и анти-цели

- **Не цели:** оплата и монетизация (отдельный этап); разбор свободного текста через LLM; проверка «тот ли товар на фото»; новые категории (телефоны, мебель); веб-кабинет продавца; парсинг каналов и чужих сайтов.
- **Анти-цели (провал, даже если всё работает):**
  - чужие данные без согласия: объявление публикуется только после явного согласия продавца с правилами;
  - мусор на сайте: проданные, устаревшие и мошеннические объявления не должны висеть;
  - владелец тонет в проверках: если «спорного» становится много, правила нужно менять, а не проверять вручную;
  - утечка контактов: контакт продавца показывается только на странице его предложения.

## 4. Решения владельца

1. Данные вводятся кнопками и короткими ответами, без LLM (вариант Б). LLM вариант А добавляется позже.
2. Объявление привязывается к товару каталога. Если модели нет, оно идёт владельцу на проверку.
3. Значения числовых фильтров строятся из данных, а не из кода: появилась видеокарта на 24 ГБ — в фильтре «24 ГБ» появляется сама. Допустимые диапазоны защищают от мусора.
4. Значения-названия (сокет, серия, чипсет) добавляет владелец вручную, чтобы опечатки не превращались в пункты фильтра.
5. Новые категории добавляет только владелец.
6. Фото от продавца обязательны. Проверка фото сервисом модерации (непристойное, насилие). Проверка «тот ли товар» через LLM добавляется позже.
7. Монетизация в этот этап не входит. Лимит активных объявлений на продавца задаётся настройкой.
8. Владелец проверяет спорное в отдельном Telegram-чате с карточкой и кнопками [Опубликовать] [Отклонить].

## 5. Подходы

|                     | Суть                                                                                                           | Выбор                                                         |
| ------------------- | -------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------- |
| 1. Внутри сайта     | Telegram шлёт сообщения на `/api/telegram` в Next.js на Vercel; состояние разговора в Neon; фото в Vercel Blob | выбран владельцем                                             |
| 2. Отдельный сервис | бот на Neon Functions, пишет в ту же базу                                                                      | отклонён: второй деплой и секреты, лишнее для текущих объёмов |
| 3. Свой сервер      | long polling на VPS                                                                                            | отклонён: платный сервер и обслуживание                       |

Логика бота лежит в отдельном модуле, чтобы при росте его можно было вынести.

## 6. Разговор с ботом

```
/start → язык (O'zbek / Русский) → правила → [Согласен]
[Продать]
 1. Категория:  [Процессор] [Видеокарта] [Плата] [ОЗУ]
 2. Бренд / модель из каталога или [Нет в списке]
 3. Состояние:  [Новый] [Б/у]
 4. Цена:       текстом, «4.2 млн» или «4200000» (тот же разбор, что в поиске сайта)
 5. Город:      кнопки из списка городов
 6. Описание:   20–1000 символов
 7. Фото:       от 1 до 5
 8. Проверка:   карточка → [Опубликовать] [Изменить]
```

- Если поле не заполнено или не проходит правило, бот переспрашивает именно его.
- Контакт: Telegram-ник. Если ника нет, бот просит поделиться номером кнопкой Telegram.
- `/my`: свои объявления, кнопки [Снять] и [Изменить цену].
- Через 30 дней бот спрашивает «Ещё продаёте?»; без ответа объявление скрывается.

## 7. Обязательные поля предложения

Категория, товар из каталога (или заявка на новый), состояние, цена в сумах, город из списка, описание 20–1000 символов, 1–5 фото, контакт, согласие с правилами. Характеристики (сокет, память, частота и т.п.) продавец не вводит: они берутся из товара каталога.

## 8. Модерация

Три исхода: **разрешено** (публикуется), **запрещено** (отклоняется, продавцу коротко пишется причина), **спорно** (владельцу).

Автоматические проверки:

- лимит новых объявлений в день и лимит активных на продавца (настройки);
- дубли: то же объявление дважды;
- цена в допустимом диапазоне; цена сильно ниже других предложений на тот же товар → спорно;
- ссылки, телефоны и слова из стоп-списка в описании → спорно;
- фото: сервис модерации; непристойное → запрещено, сомнительное → спорно;
- первые 3 объявления нового продавца → спорно (потом продавец «доверенный»);
- модель не из каталога, новое значение названия-фильтра → спорно.

После публикации: кнопка «Пожаловаться» на странице предложения; 3 жалобы от разных людей → предложение скрывается и уходит владельцу.

## 9. Данные

Новые сущности в Neon (точные поля уточняются при планировании):

- `Seller`: Telegram id, ник, язык, согласие и его дата, флаг «доверенный», блокировка;
- `Offer` расширяется: статус (`pending`, `published`, `rejected`, `hidden`, `expired`), описание, срок жизни, ссылка на продавца;
- `Photo`: ссылка на Blob, порядок, результат проверки;
- `Report`: жалобы;
- `Conversation`: шаг и черновик разговора с ботом.

Числовые значения фильтров считаются запросом по данным, с допустимым диапазоном для каждого фильтра. После публикации сайт сбрасывает кэш каталога (`revalidateTag`).

## 10. Ограничения

- Весь код на TypeScript, тот же стек: Next.js 16, Prisma 7, Neon, Vercel.
- Секреты (токен бота, ключи сервисов) только в переменных окружения Vercel, не в чате и не в git.
- Бот отвечает на узбекском (латиница) и русском.
- Расходы на этом этапе: ожидаются около нуля (бесплатные тарифы); точные лимиты Vercel Blob и сервиса модерации проверяются при планировании.
- Для разбора цены и числовых значений используется уже существующий код поиска.

## 11. Оставлено разработчику

- Библиотека бота (предполагается grammY).
- Выбор сервиса модерации фото и проверка его цены и доступности из Узбекистана.
- Точные поля таблиц, миграции, имена.
- Тексты сообщений бота на двух языках (согласуются с владельцем).
- Тексты правил для продавца (требует юридической проверки; в черновике просто и понятно).
- Список городов и стоп-слов.
- Защита webhook: проверка секретного токена Telegram.

## 12. Будущее (вне этапа)

- Разбор свободного текста и проверка фото через LLM (Haiku 5.5, после eval).
- Монетизация: платные объявления сверх лимита, поднятие, тарифы для магазинов.
- Фиды магазинов (формат YML или Google Merchant, по договорённости с магазином; публичного API у площадок Узбекистана найти не удалось, проверено 2026-11-22) и новые категории.
